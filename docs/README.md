## 文档状态

- **当前规范**：执行时必须遵守。
- **当前实现**：只描述已验证代码。
- **规划目标**：未来工作，必须包含周期和验收条件。
- **参考材料**：调研、原型、论文或素材。
- **历史快照**：只代表特定日期，不作为当前状态。
- **生成产物**：必须与源规格和校验回执成组维护。

## 维护规则

1. 新文档进入对应分类，不在 `docs/` 根目录堆放。
2. 用户功能变化同步 README/PRD；运行时变化同步架构；质量流程变化同步质量规范。
3. 重要文档顶部注明状态和日期，历史报告不得覆盖成“当前结果”。
4. 相对链接移动后必须修复；发布前执行链接和 `git diff --check` 检查。
5. 一次性脚本用后删除；可重复脚本进入 `scripts/` 并说明用途。
6. 不提交 API Key、`.env.local`、运行数据库、用户隐私数据或构建产物。

完整规则见 [项目治理与文档规范](00-项目治理/项目治理与文档规范.md)。
