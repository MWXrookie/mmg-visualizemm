> 版本：v1.1 ｜ 日期：2026-08-29 ｜ 状态：评审稿
> 关联：[PRD.md](../PRD.md)（功能需求 F 编号）｜[docs/UI-UX设计.md](UI-UX设计.md)｜[docs/技术框架与架构.md](技术框架与架构.md)

## 1. 开发原则

| 原则 | 说明 |
|------|------|
| 单人轻量 | 全栈 TypeScript（前后端同栈），避免重型框架/微服务 |
| 主线优先 | 按「读题主线」推进（M0→M2 为核心价值快路径），知识卡片/编程后置 |
| 验收先行 | 每个任务先写验收标准再写代码，防止"做完了不知道做没做对" |
| 评测驱动 | AI 相关功能（角色判定）用内置评测集量化验收，不靠感觉 |
| 渐进增强 | 沙箱/可视化双轨：先 Pyodide + matplotlib 最简单路径，Docker/Plotly 交互后加 |
| **设计先行（新增）** | 开工前先用 **OpenDesign 消费 `design-systems/mmg_visualizemm/DESIGN.md`** 产出核心页面高保真原型，评审通过后才进入编码；实现阶段以「原型 + 设计文档」为基准 |
| **先功能后 UI（2026-08-29 决策）** | 当前阶段**功能优先**：先完善读题/划词/对话/卡片等核心功能闭环，UI 精细打磨（对齐 OpenDesign 原型）**后置**到功能稳定后统一进行；开发期保持 tokens 一致即可，不做像素级 UI 调整 |

## 2. 技术栈（已定案，回顾）

| 层 | 选型 |
|----|------|
| 前端 | React 18 + TypeScript + Vite + React Router |
| 后端 | Node.js + Fastify（或 Next.js API Routes） |
| 数据库 | SQLite（better-sqlite3 或 Prisma） |
| AI 接入 | OpenAI 兼容协议直连多 Provider；Key 浏览器端 AES-GCM 加密存储（ai.diy 架构），服务器仅轻中继 |
| 流式 | SSE |
| 文件解析 | exceljs（Excel）/ pdf-parse 或 PDF.js（PDF）/ tesseract.js（图片 OCR，可延后） |
| 代码执行 | Pyodide（默认）/ Docker 沙箱独立服务（可选） |
| 可视化 | matplotlib→base64（默认）+ Plotly/ECharts iframe（交互）；卡片演示 GeoGebra/Desmos 嵌入（非商业署名） |
| 数学渲染 | KaTeX |
| 图标 | Phosphor（SVG） |
| 部署 | `npm install && npm start` / Docker Compose（可选） |
| **设计工具（新增）** | **OpenDesign**（[nexu-io/open-design](https://github.com/nexu-io/open-design)，Apache-2.0）：消费 `design-systems/mmg_visualizemm/DESIGN.md` 生成高保真 HTML 原型；官方支持 DeepSeek Harness（dsh）运行时；产出导出至 `docs/prototypes/` |

## 3. 里程碑任务拆解（WBS）

### M-P 设计原型（新增，预计 0.5-1 周，先于 M0）

> 用 OpenDesign 把设计系统转成可见的高保真原型，**评审通过后才开始写代码**。这是"设计先行"原则的落地。

| 任务 | 内容 | 产出 | 验收标准 |
|------|------|------|---------|
| T-P1 设计系统就绪 | 确认 `design-systems/mmg_visualizemm/DESIGN.md` 与 `docs/UI-UX设计.md` 一致（tokens/组件/排版） | DESIGN.md（已完成 ✅） | 两份文档无冲突；缺失项以 UI-UX 文档为准补 DESIGN.md |
| T-P2 核心页原型 | 用 OpenDesign 加载 DESIGN.md，生成 4 个核心页面原型：**读题工作台（含划词交互态）/ AI 解读与对话区 / 知识卡片 / BYOK 设置页** | `docs/prototypes/` 下 HTML 文件 | 原型覆盖全部 P0 页面；可交互（划词工具栏可触发） |
| T-P3 一致性检查 | 逐页对照 `docs/UI-UX设计.md` 检查：配色（角色判定语义色）/ 字号字阶 / 间距 / 组件规格 / 排版骨架 | 检查记录 | 偏差清单 ≤10 项；严重偏差（配色/布局结构）为 0；偏差修复或回写文档 |
| T-P4 交互确认 | 重点评审**划词精读交互**（选区→工具栏→角色卡→双向引用）的动线与视觉 | 交互确认记录 | 作者确认交互方向；若调整则同步更新 UI-UX 文档与 DESIGN.md |
| T-P5 原型归档 | 导出 HTML/截图归档，作为后续实现的视觉基准 | `docs/prototypes/` 完整归档 | 每个原型文件头部注明对应页面与 PRD 功能编号 |

**M-P 出口**：核心页原型经作者评审通过，实现阶段可对照原型编码。

### M0 项目骨架（预计 1 周）

| 任务 | 内容 | 产出 | 验收标准 |
|------|------|------|---------|
| T0.1 前端脚手架 | Vite+React+TS+路由+设计 tokens（CSS 变量落地，**对照 M-P 原型**） | 应用壳 + 5 个路由占位页 | `npm run dev` 启动，路由可跳转，tokens 生效（无硬编码色值）；**页面视觉与原型一致** |
| T0.2 后端脚手架 | Fastify + SQLite + SSE 基础 | 健康检查 API + SSE 通道 | `GET /api/health` 返回 ok；SSE 客户端收到测试流 |
| T0.3 BYOK 设置页 | 多 Provider 预设 + 自定义端点 + Key 加密存储 + 模型切换 | 设置页（UI-UX §4.5） | Key 存 IndexedDB/localStorage 加密；刷新不丢失；**换浏览器不可见**（预期行为） |
| T0.4 连接测试 | 填 Key 后调用最小模型请求验证 | 测试按钮 + 错误分类提示 | 无效 Key/网络错误/余额不足三类错误分别给出人话提示 |
| T0.5 Key 新手指引 | 内置 3 分钟图文申请教程（DeepSeek 等国内平台） | 设置页内指引 | 无 API 经验的新生按指引 10 分钟内完成配置 |

**M0 出口**：新生下载 → `npm install && npm start` → 10 分钟配好 Key → 连接测试通过。

### M1 上传与 AI 读题（预计 1-1.5 周）

| 任务 | 内容 | 验收标准 |
|------|------|---------|
| T1.1 上传组件 | 题目文本粘贴 + 图片 + Excel/PDF 多文件 | 拖拽/点击上传；文件类型校验；进度展示 |
| T1.2 解析管线 | exceljs/pdf-parse → 结构化文本+表格（保留列名/行列） | Excel 含中文列名+100 行数据解析正确；PDF 表格尽力提取 |
| T1.3 解析预览 | 展示题干与表格预览，可修正 | 表格以网格预览；可编辑错误单元格 |
| T1.4 AI 整体解读 | 读题 prompt + SSE 流式 + 数据联动（表列↔题干术语） | 输出 5 要素（问题/条件/目标/数据清单/输出要求）；列名↔术语关联准确率 ≥80%（评测集） |
| T1.5 会话初始化 | 上传即建会话，内容持久化 | 刷新后会话内容仍在（SQLite） |

**M1 出口**：一道题+1 Excel，5 分钟内完成「上传→解析→整体解读」。

### M2 划词精读（核心差异化，预计 1.5-2 周）

| 任务 | 内容 | 验收标准 |
|------|------|---------|
| T2.1 划词交互 | Selection API + 浮动工具栏（AI解读/提问/复制） | 选区<500 字；工具栏不遮挡选区；键盘可达；移动端可取消 |
| T2.2 角色判定引擎 | 结构化 prompt（角色分类+置信度+解释+影响）+ 输出解析 | **内置评测集 10 道题 ≥90% 角色判定正确率**（见 §5.3） |
| T2.3 双向引用 | 答案脚注↔原文高亮跳转 | 点击脚注滚动到原文并闪烁高亮；反向（原文→卡片）成立 |
| T2.4 连续深挖 | 选区作为锚点带入对话 | 对话首条自动携带选区上下文，追问不丢失 |
| T2.5 质疑机制 | 置信度展示 + 质疑重论证 | 质疑后 AI 给出重论证与置信度变化 |

**M2 出口**：新手选中任意一句题干 → 10s 内得到「角色+置信度+解释+影响」卡片，引用可回跳。

### M3 对话深挖（预计 1 周）

| 任务 | 内容 | 验收标准 |
|------|------|---------|
| T3.1 多轮上下文 | 题目+附件摘要+已解读+历史消息 → 模型 | 30 轮内上下文不丢失关键信息 |
| T3.2 问题链引导 | Socratic prompt：目标函数→约束→数据→模型选型→为什么 | 对话中出现引导步骤指示器（①读题②精读③方向） |
| T3.3 反问与防代做 | AI 反问 + 引导模式开关 + 提示样式 | 默认引导模式下 AI 不输出成品答案，只给思路与反问 |
| T3.4 反馈闭环 | 👍/👎 + 重新生成 | 反馈可提交本地；重新生成可用 |

**M3 出口**：用户对话后能用自己话说出「模型选型 + 理由」。

### M7 三台架构重构（2026-08-29 决策，产品结构重大调整）

> **背景**：经产品评审，确认新架构为「三台流水线」——**读题工作台 → 建模思路梳理台（问题拆解）→ 编程工作台**，套在统一壳（左功能栏 20% 可折叠 + 右内容区 80%）内。
> **定位**：帮助新手入门理解（不代做）。原 M1-M5 已实现能力（上传解析/划词/卡片/编程）**保留并迁入三台**。
> 对话功能**暂不做**（待用户测试验证需求）；知识卡片完全内嵌、无独立入口。

| 任务 | 内容 | 验收标准 |
|------|------|---------|
| T7.1 全局壳 | 左功能栏（三台导航+底部设置，可折叠成图标窄栏）+ 右内容区；沉浸态（读题/梳理台收起左栏、主区+书签竖栏+AI 栏 30%） | 三台切换正常；左栏折叠/展开；比例 20% 可调 |
| T7.2 **资料抽屉** | 三台共用右侧「题干+附件」抽屉，可收起/展开，随时查看、不打断当前工作；支持把表格/题干片段「引用到当前」 | 任意台打开抽屉可看题干与全部附件预览；引用不打断当前操作 |
| T7.3 **数据→代码注入** | 编程台从附件一键生成「数据读取 + 绘图」代码骨架（附件转代码可用数据/CSV，自动拼接 pandas/matplotlib 代码） | 上传 Excel 后一键生成可运行的读取+绘图代码，产出区出图 |
| T7.4 思路梳理台 | 问题选择器（问题1/2…独立）+ 拆解块（可折叠/可编辑/可新建/可关联）+ AI 栏（对话书签+知识卡片书签，AI 修改走预览→确认→落盘） | 可建多个拆解块并编辑；AI 对话可指挥编辑（预览确认）；知识卡片可查可随对话出现 |
| T7.5 编程台可视化 | 左右对半：左代码区（✨AI生成/改进按钮+输出日志）/ 右产出区（图表可视化+调参面板实时反馈） | AI 生成弹窗（选拆解块+自然语言）产出代码草稿；参数改动即时重算刷新图表 |

**M7 出口**：三台闭环可用——读题要素可被引用、思路拆解可组织、附件数据一键注入代码并可视化。

## 6. 测试策略

### 6.1 自动化测试（聚焦高风险）

| 模块 | 测试内容 |
|------|---------|
| 解析管线 | Excel 中文列名/多 sheet/空值；PDF 表格提取 |
| Key 加密存储 | 加密-解密往返；存储无明文 |
| 角色判定输出解析 | LLM 返回 → 结构化 JSON 解析鲁棒性（坏输出兜底） |
| 会话 CRUD | SQLite 读写/删除/导出 |

### 6.2 评测集（AI 质量量化）

- **角色判定评测集**：10 道历年数模题，每道人工标注 5-8 个关键句段的正确角色 → 作为 CI 或手动回归基准，**阈值 ≥90%**
- 解读评测：5 道题检查 5 要素齐全

### 6.3 手动用例清单（关键路径）

1. **新生全流程**：下载→启动→填 Key→测试→上传题+Excel→整体解读→划词→角色卡→追问→（卡片→编程→出图）
2. **错误路径**：坏 Key / 断网 / 不支持的文件 / 超大文件 / AI 超时 / LLM 返回坏格式
3. **数据持久**：刷新、关浏览器重开、导出
4. **兼容**：Chrome/Edge 最新版；375px 与 1440px 视口
5. **原型比对（新增）**：M0-M2 每个里程碑出口，对照 `docs/prototypes/` 原型逐屏走查
