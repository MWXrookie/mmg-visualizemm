# MMG 金标准评测集规范

> 状态：当前规范
> 版本：v1.2
> 更新日期：2026-09-28
> 适用范围：MMG 从题目导入、读题理解、题干—附件联动、建模引导到代码运行与结果保存的完整闭环

## 1. 目的与非目标

金标准集为项目提供可重复、可审计的质量基线，用于判断 prompt、RAG、文件解析、工作区和交互变化是否造成进步或回归。它不是模型排行榜，也不要求 AI 复述某篇论文的唯一方案。

首版目标：

- 固定 10 道具有代表性的数学建模任务；
- 同时覆盖输入完整性、语义理解、证据联动、建模合理性和执行结果；
- 将确定性产品回归与有波动的真实模型评测分开；
- 为创新项目立项提供可复现的评测方法、失败样本和版本对比证据。

首版非目标：

- 不评价竞赛论文写作质量或证明方案达到竞赛最优；
- 不把获奖论文使用的方法规定为唯一正确答案；
- 不在默认 CI 中调用真实模型、外部 Embedding 或付费服务；
- 不测试当前产品尚未支持的 PNG/JPG 图像理解；几何题只使用文本、坐标和表格输入；
- 不以扩充样本数量替代人工复核和失败分析。

## 2. 五小时开发包

本工作按最多 5 小时的独立开发包推进。每包结束时必须形成可审阅产物、执行适用检查并停止；未完成内容进入下一包，不临时扩大范围。

| 开发包 | 目标 | 退出条件 | 状态 |

| G2 框架起步 | 加载器、校验器、结果目录及 2 道原创题 | 无外部服务即可验证样本格式和确定性断言 | 已完成 |
| G3 原创题完成 | 再完成 4 道原创题 | 6 道原创题均有基线程序与人工标注 | 已完成 |

## 4. 单题目录与文件契约

正式样本放入 `tests/fixtures/golden/cases/<case-id>/`。目录名和 `manifest.json` 中的 `id` 必须一致。

面向用户的建模范例目录由 `scripts/generate/public-examples.mjs` 从正式集生成到 `web/public/examples/`。生成前复核许可标记、来源类型、文件哈希和十题数量；只发布题干、附件、署名与改编信息。评分期望、参考基线、原始来源快照及 `compatibility/` 内容均不进入浏览器静态目录。范例可供用户学习，评测仍使用独立的夹具和运行记录。

```text
case-id/
├── manifest.json       # 身份、版本、来源、许可、文件和覆盖信息
├── problem.md|txt|pdf  # 题干；具体名称写入 manifest
├── attachments/        # 可为空；只放完成题目所需附件
├── source/             # 开放数据题保留已核验原始快照；原创题不需要
├── provenance.json     # 开放数据题必需：DOI、许可、快照哈希和改编步骤
├── expected.json       # 人工标注、可接受边界、禁止错误和断言
├── baseline.mjs|py     # 可选但推荐；给出可复现的最低基线
└── README.md           # 人工步骤、设计说明和已知限制
```

所有 JSON 文件使用 UTF-8、两个空格缩进，不含注释。日期使用 ISO 8601，文件路径使用相对路径和 `/`。数据文件不得包含 API Key、真实用户数据或可识别个人信息。

机器可读契约位于：

- `tests/fixtures/golden/schemas/manifest.schema.json`
- `tests/fixtures/golden/schemas/expected.schema.json`
- `tests/fixtures/golden/schemas/run-result.schema.json`
- `tests/fixtures/golden/schemas/rubric-anchors.schema.json`
- `tests/fixtures/golden/schemas/provenance.schema.json`

## 5. 来源与版权政策

### 5.1 来源优先级

1. 原创合成题和自行生成的数据；
2. 明确允许再使用和改编的开放数据；
3. 已经在仓库中的复杂真题，仅作为兼容性样本；
4. 其他来源只有取得明确许可后才能进入可发布评测集。

禁止从答案站、论坛转载、网盘或来源不明的题库直接复制题目、附件或答案。官方可下载不等于允许重新分发。

### 5.2 开放数据进入条件

每个外部数据集必须逐项记录：

- 数据集名称、原始页面、提供者和访问日期；
- 具体许可证及许可证页面；
- 所需署名文本；
- 是否允许修改和再分发；
- 本项目进行了哪些筛选、聚合、翻译或合成处理；
- 是否包含第三方字段或额外限制。

只有 `redistributable=true` 且许可证信息经过人工复核的数据才能提交到公开仓库。许可证不明确时，只保存来源清单，不下载或提交数据。

### 5.3 真题和论文边界

- 官方真题用于验证真实长度、附件和结构，不推定其为开放许可内容；
- 获奖论文只能作为方法参考和人工复核材料，不复制为 `expected.json`；
- 标准答案描述“必须满足的事实、约束和合理方法边界”，允许多种正确模型；
- 对外发布前再次检查题目、附件、论文摘录、Logo 和截图的授权状态。

### 5.4 已核验并采用的开放来源

核验日期：2026-09-28。以下结论来自每个 UCI 数据集的具体官方页面，不以平台的一般政策代替逐项许可核验。

| 样本 | 官方来源 | DOI | 许可与改编 |
|---|---|---|---|
| G01 | [UCI Energy Efficiency](https://archive.ics.uci.edu/dataset/242/energy+efficiency) | `10.24432/C51307` | CC BY 4.0；固定抽取 12 行、重命名字段并增加追溯 ID |
| G03 | [UCI Bike Sharing](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset) | `10.24432/C5W894` | CC BY 4.0；把日级数据按自然月求和为 24 行 |

## 6. 参考依据与评价方法

### 6.1 依据映射

本规范不声称照搬任何单一标准，也不把项目自定阈值包装成外部公认分数。评价构念分别来自下列公开依据，再按 MMG 的教学辅导和软件闭环场景进行操作化。

| 依据 | 采用的原则 | 在 MMG 中的落点 |
|---|---|---|
| [OECD PISA 2022 Mathematics Framework](https://www.oecd.org/en/publications/pisa-2022-assessment-and-analytical-framework_dfe0bf9c-en/full-report/component-3.html) | 数学建模过程包含 formulate、employ、interpret/evaluate | 形成问题、执行数学方法、解释和检验结果三个核心维度 |
| [COMAP MCM/ICM 官方参赛与评审指引](https://www.contest.comap.com/undergraduate/contests/mcm/instructions.php) | 明确变量与假设、论证模型、测试误差/敏感性/稳定性、讨论优缺点、清楚报告结果并记录来源 | 建模完整性、验证意识、沟通与引用；同时尊重其“不设置统一及格分”的说明 |
| [RAGAS 原始论文（EACL 2024）](https://aclanthology.org/2024.eacl-demo.16/) | 区分回答忠实度、回答相关性和上下文相关性 | 题干/附件/RAG 的证据支撑率、回答相关性、上下文精确率与召回率 |
| [NIST AI RMF Generative AI Profile](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf) | 记录数据来源、许可、版本、人类监督、TEVV 历史和持续监测；区分系统与第三方风险 | 来源登记、运行身份、失败归因、重复评测和人工复核 |
| [HELM](https://arxiv.org/abs/2211.09110) | 场景覆盖、多指标评价、标准化条件并公开缺失范围 | 题型矩阵、相同配置复跑、分维度报告而非只报一个总分 |
| [Standards for Educational and Psychological Testing](https://www.testingstandards.net/) | 分数解释必须对应明确用途并提供效度、信度/精度和决策一致性证据 | 限制评分用途、建立锚点样例、复核评分一致性，不提前宣称量表“有效” |
| [ISO/IEC 25010:2023 官方摘要](https://www.iso.org/standard/78176.html) | 软件产品质量需要多特性评价 | 输入、可靠性、恢复、安全和可用性使用工程门禁；不宣称项目已经通过 ISO 认证 |

其中“保持用户主导、AI 不默认代做”是 MMG 的产品目标，不是上述标准的原文要求，必须在报告中明确标为项目自定义维度。

### 6.2 工程门禁：通过/不通过

工程正确性不与主观建模分数混合。以下四项全部通过，样本才进入建模质量评价：

| 门禁 | 内容 | 主要证据 |
|---|---|---|
| E1 输入完整性 | 文件、页码、工作表、字段、单位和关键数值未丢失 | 自动断言 |
| E2 状态可靠性 | 保存、刷新、导出和导入后关键内容一致 | API/浏览器测试 |
| E3 执行正确性 | 基线代码可运行，数值满足硬约束，输出可定位 | 自动断言 + 浏览器复核 |
| E4 安全与来源 | 无密钥/隐私泄漏，外部数据和引用可追溯 | 自动扫描 + 人工复核 |

任一门禁失败即判定该题工程闭环失败，不能用较高的语言质量分抵消。

### 6.3 建模质量量规：分维度报告

每个维度使用 0–3 四级量规，不加权成伪精确的百分制。总和仅作描述性摘要，不能覆盖单维度失败。

| 维度 | 参考依据 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|
| M1 形成问题 | OECD formulate、COMAP | 未识别目标/变量/约束，或与题意冲突 | 识别部分要素但有关键遗漏 | 目标、变量、约束和合理假设基本完整 | 结构完整，并解释简化、单位和边界 |
| M2 执行与推理 | OECD employ、COMAP | 方法不可用或推理错误 | 方法方向可理解但存在重大缺陷 | 方法适配题目，步骤与计算基本正确 | 方法选择有论证，并有稳健实现或合理替代比较 |
| M3 解释与评价 | OECD interpret/evaluate、COMAP | 结果未回到情境或明显不合理 | 有结论但缺乏合理性检查 | 正确解释结果并检查主要约束 | 还分析误差、敏感性/稳定性、局限与适用范围 |
| M4 证据与忠实性 | RAGAS、COMAP | 关键事实捏造或来源不存在 | 部分关键主张无支撑或引用错位 | 关键主张可回到题干、附件或知识库 | 支撑完整、定位准确，并能区分题目事实、假设与外部知识 |
| M5 沟通与用户主导 | COMAP + MMG 自定义 | 输出不可理解，或越权覆盖用户决定 | 结构混乱、解释不足或过早代做 | 结构清晰，给出可执行下一步并保留用户确认 | 简洁清楚地暴露取舍、不确定性和可质疑节点 |

评分锚点必须随正式样本一起保存：每个维度至少包含一个 0、1、2、3 级示例或边界说明。没有锚点时只能记录观察，不能宣称评分具有一致性。

### 6.4 通过规则与阈值校准

COMAP 官方指引明确没有统一及格分；OECD、NIST、RAGAS 和 ISO 也不会为 MMG 给出“80 分即通过”的阈值。因此原 v1.0 草案中的 80/85 分线已撤销。

当前规则：

1. 工程门禁 E1–E4 全部通过，且不存在阻断项；
2. M1–M5 分维度报告，在真实模型校准前不设置总分及格线；
3. G2/G3 的六道原创样本用于建立锚点和确定性基线；项目内部阶段阈值只能在 G6 至少三次真实模型运行与人工复评后校准；
4. 阈值必须记录样本表现、误判代价和人工复核理由，并明确标记为“MMG 项目门槛”，不得表述为外部标准；
5. 改变量规、锚点或阶段阈值必须提升评测集版本，历史结果不得直接混合比较。

### 6.5 证据和检索指标

金标准集有人工标注时优先使用可核对的直接指标，不只依赖另一个 LLM 打分：

- **主张支撑率**：有题干、附件或知识库证据的关键主张数 / 全部关键主张数；
- **引用定位正确率**：文件、页码/工作表、字段或原文定位正确的引用数 / 全部引用数；
- **上下文召回率**：被检索到的必需证据片段数 / 标注的全部必需证据片段数；
- **上下文精确率**：检索结果中相关片段数 / 全部返回片段数；
- **回答相关性**：是否覆盖题目要求且没有大段无关内容，按锚点人工评分。

RAGAS 提供概念和自动化候选方法，但 MMG 不把 LLM-as-judge 当作唯一裁判；自动分数必须与人工标注抽样比对。

### 6.6 可靠性与复核

- 日常开发可每个配置运行 1 次，只作为回归信号，不宣称稳定性；
- 阶段验收对目标配置至少重复 3 次，报告均值、范围、失败次数和原始结果，不只挑最好一次；
- Prompt、模型、参数、知识库、样本版本和运行环境必须固定并记录；
- 正式立项报告前，10 道题应由第二位人工复核者独立评分；报告逐维度一致率，并视数据类型采用加权 Cohen's kappa 等一致性指标；
- 只有一名人工评分者时必须明确写作“内部形成性评价”，不得宣称评分者间信度已经建立。

### 6.7 阻断项

- 题干或必需附件无法读取；
- 工作区保存、刷新或备份恢复后关键字段丢失；
- 引用不存在的附件、工作表、字段或原文；
- 捏造关键数据，或将外部常识伪装为题目事实；
- 生成代码无法执行且没有可理解的错误或恢复路径；
- 优化结果违反硬约束，预测/分类出现明确数据泄漏；
- 输出包含密钥、个人信息或未披露的外部数据；
- 未经用户确认直接覆盖原题、附件或已有工作区内容。

### 6.8 自动与人工边界

自动检查负责文件完整性、JSON 合规、字段引用、数值区间、硬约束、代码退出状态和工作区一致性。人工复核负责方法合理性、解释质量、替代路径、教学引导和严重误导。退出码为 0 不能单独证明建模正确。

开放式答案按“必要要点、可接受替代、禁止错误和分级锚点”标注，不按字符串完全匹配。评测人员不能因模型选择不同于基线程序而直接扣分。

## 7. 版本与运行记录

### 7.1 版本规则

- 样本集版本使用 `major.minor.patch`；首版为 `1.0.0`。
- 修改题意、答案边界或评分会影响可比性，至少提升 minor。
- 只修正文案、路径或不影响结果的元数据时提升 patch。
- 删除或替换题目、改变总分结构时提升 major。
- 每次真实模型评测记录 git SHA、样本集版本、prompt 版本和知识库版本。

### 7.2 结果分层

- `deterministic`：无需外部服务的解析、断言、工作区和基线程序结果，可进入 CI；
- `mocked`：使用固定替身的产品流程结果，可进入 CI；
- `live-model`：真实模型结果，有网络、费用和波动，不进入默认 CI；
- `manual`：浏览器人工复核、解释质量和教学行为。

真实模型失败必须区分产品缺陷、模型质量、外部服务和评测环境，不能把所有失败合并成一个通过率。

## 8. 防泄漏与防过拟合

- 正式题目不得写入系统 prompt、few-shot 示例或知识库正文；
- 开发调试优先使用非正式样本，金标准只用于阶段验收；
- 每类至少保留一个未用于 prompt 调试的样本；
- prompt 或 RAG 变化必须同时报告通过项和失败项；
- 不因单次模型输出不理想而修改标准答案迎合模型；
- 未来扩展时建立私有挑战集，公开集用于复现，私有集用于防止针对性调参。
