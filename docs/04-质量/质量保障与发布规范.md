# MMG_VisualizeMM 质量保障与发布规范

> 状态：当前规范
> 更新日期：2026-09-28
> 目标：让单人 + AI 开发仍然具备可重复、可审计的质量门。

## 1. 当前强制检查

每次提交前执行统一质量入口：

```bash
npm run check
npm run test:browser
git diff --check
```

`npm run check` 当前依次执行 Node 内置单元/API/金标准契约测试、三个服务端入口的语法检查和前端生产构建。API 测试已覆盖工作区 CRUD、带版本备份恢复、附件 TXT/CSV/XLSX/PDF 解析、表格导出、健康检查以及本地哈希 RAG 检索；金标准测试校验 Schema、路径边界、SHA-256、原文引用、6 道原创题与 3 道开放数据题的确定性基线，并交叉核对开放数据 DOI、许可、原始快照和改编输出。`npm run test:browser` 会重新构建前端并在 Chromium 中验证无 Key 设置、TXT 题干上传、拆解块、编程台入口、备份导入导出与刷新恢复；其余用例使用本地确定性替身验证整体解读、划词角色卡、代码生成与持久化、Pyodide 文本/图表输出、图表放大和 CDN 断网错误。GitHub Actions 会在 push 和 pull request 时执行两组检查。

涉及浏览器功能时还必须实际操作相关页面。构建通过不能替代交互、数据和 AI 质量验收。

## 2. 当前与后续自动化入口

当前已具备 `npm test`、`npm run test:api`、`npm run test:golden`、`npm run test:browser` 和最小 CI。首次在本机执行浏览器测试前运行 `npx playwright install chromium`。P1 后续继续补齐：

```bash
npm run lint
npm run test:browser:model
```

后两个脚本仍是规划项，在真正加入 `package.json` 前不得在验收报告中声称已具备。当前 API 与浏览器测试都使用独立临时数据目录，不读写真实 `data/mmg.db` 或 `data/knowledge_cache.json`，并通过 `MMG_FORCE_LOCAL_EMBEDDING=1` 禁止请求外部 Embedding；浏览器测试结束后会停止隔离服务并清理临时目录。`scripts/eval/` 中需要显式凭据的外部模型评测不属于默认 CI 测试。

## 3. 测试分层

| 层 | 覆盖重点 | 触发 |
|---|---|---|
| 单元测试 | 文本解析、代码提取、卡片匹配、工作区合并、CSV、RAG 打分 | 每次提交 |
| API 测试 | 工作区 CRUD、附件解析、知识搜索、SSE 错误与健康检查 | 每次提交 |
| 金标准契约 | Schema、路径、哈希、原文证据、原创题基线与确定性断言 | 每次提交 |
| 浏览器冒烟 | 设置、TXT 上传、拆解、导航、备份恢复、模拟解读/划词/生成、模拟 Python 文本/图表输出、Pyodide 断网 | 合并前/CI |
| AI 评测 | 角色判定、引导策略、RAG、引用正确性 | prompt/模型/知识库变化 |
| 人工可用性 | 键盘、主题、窄屏、文案、失败恢复 | 每个候选版本 |
| 安全与隐私 | Key、日志、数据库、XSS、代理、依赖和外部请求 | 每个发布版本 |

## 4. 核心人工冒烟流程

- [ ] 全新启动，无 Key 时能找到设置并理解下一步。
- [ ] 测试有效 Key、无效 Key、额度不足、断网和代理失败。
- [ ] 上传 XLSX/CSV/PDF/TXT；损坏、不支持和超大文件有清晰提示。
- [ ] 整体解读、划词角色判定、引用定位和连续追问正常。
- [ ] 建模拆解块可增删改、确认 AI 修改并刷新恢复。
- [ ] 代码生成、Pyodide 运行、文本输出、图表和错误提示正常。
- [ ] 工作区导出、删除、导入和恢复后数据一致。
- [ ] 深浅主题、键盘操作、1440×900、1280×720 和窄屏基本可用。

## 5. AI 功能验收

金标准题的题型矩阵、来源政策、评分和运行记录遵循[金标准评测集规范](金标准评测集规范.md)。

- 评测集必须固定版本，样本不能只来自成功案例。
- 记录 prompt 版本、模型、日期、采样参数、通过率和失败类型。
- 外部模型波动与产品代码回归分开统计。
- 对角色判定使用 precision、recall、F1 和混淆矩阵。
- 对 RAG 使用 Recall@k、来源正确性和无关片段率。
- 对引导策略统计是否先提问、是否等待用户、是否越权直接给完整方案。
- 严重错误要保留原始输入、脱敏输出和修复回归用例。

## 6. 安全与数据检查

- API Key 不进入 SQLite、日志、截图、评测数据或 git。
- 局域网 HTTP 的明文降级必须显著提示，不能宣传为“始终加密”。
- Markdown/HTML 输出经过清洗，文件名和错误信息不能形成注入。
- 工作区备份默认不包含 Key 和服务端环境变量。
- 用户研究材料先取得知情同意，去标识化后再分析或展示。
- 外部模型、Embedding、CDN 和代理都应在隐私说明中列为数据边界。
