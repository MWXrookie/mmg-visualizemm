# G6 真实模型人工评测执行准备（无模型调用）

> 日期：2026-10-01　状态：运行方案就绪，真实模型评测未执行

## 现场依据与边界

- 正式 `tests/fixtures/golden/cases/G01`–`G10` 已有可再分发来源、独立加载和确定性基线；`compatibility/G08.sources.json` 只供本地兼容测试，不进入本轮。公开“建模范例”可供浏览，不能作为模型评测结果。
- 十题真实 Chromium/Pyodide 的人工给定代码已逐题核对附件、数值和图表。它验证运行链路，不验证模型生成的代码、解释或教学行为。
- `scripts/eval/role-classification.mjs` 只覆盖独立的角色判定用例，不能作为 G6 十题全链路评测入口。当前没有 `test:browser:model` 命令，也没有自动化的十题真实模型评分器。本方案采用受控浏览器人工运行与双人复核，不虚构自动化覆盖。
- 本文件只制定下一轮执行方法。本次没有读取或修改凭据，没有启动模型服务、发送请求或产生费用。

## 启动前封存

1. 用户先明确授权本次真实模型调用的服务商、模型、费用上限和最多请求次数。没有授权时停在此处。任何“测试连接”、Embedding 或重试也计入请求；不得借用现有浏览器设置或本机 Key 擅自试跑。
2. 固定正式样本集版本、十个 `manifest.json` 的哈希、`git rev-parse HEAD`、工作树是否含未提交修改及差异摘要哈希。当前工作树有大量在途改动，单独记录快照；Git SHA 单独不足以复现结果。固定 Prompt/知识库版本或其内容哈希、服务商/模型、温度、seed（不支持则记 `null`）、浏览器/Node/操作系统版本。
3. 由不看 `expected.json`/`baseline.mjs` 的执行者只用正式题干和题目附件操作产品；评分者在输出完成后再对照 `expected.json`、独立基线、评分锚点和原始附件。正式题不得复制进系统 prompt、few-shot 或知识库。每次重复从新的空白工作区开始，不把上一轮模型答案带入下一轮。
4. 预设相同的用户操作顺序：导入题目和附件 → 整体解读 → 按产品引导完成拆解交互 → 请求生成代码 → 在 Pyodide 实际运行 → 查看文本、图表与保存恢复。人工追问、改写代码、重试和外部帮助逐步记入记录；这些介入后的结果与首次自主输出分开判定。若题目需要用户决策，按量规评价模型是否先解释并请求决定，不以人工给出最优答案代替模型能力。

## 隔离与数据流

- 使用专用浏览器资料目录及独立空白 `MMG_DATA_DIR`，不连接已有工作区数据库；评测端口与日常服务分开。先以确定性替身核对隔离目录、题目导入、保存和备份恢复，再进行授权的真实模型请求。评测结束保留目录供审计，未经授权不清除数据。
- 设置 `MMG_FORCE_LOCAL_EMBEDDING=1`，使知识库检索只走本地哈希向量，避免模型主任务之外的 Embedding 费用与额外外传。服务端当前会读取 `server/.env.local` 配置，但该开关阻止其用于外部 Embedding；主模型调用仍需要单独的浏览器 BYOK 配置。不要在截图、录屏、日志、命令行参数、运行记录或工作区备份中暴露 Key。
- 只发送正式题干、解题所需附件和预定用户交互到获授权的模型端点。原始 UCI 快照、`expected.json`、参考代码、评分锚点、兼容赛题和历史失败样本不得发送给模型。每轮记录实际请求数量、重试、服务错误和停止原因；达到授权上限即停止。
- 不启用浏览器对真实用户资料的复用，不混入真实用户题目。正式题虽已获许可，外部模型端仍属于第三方数据边界；运行前记录服务商、端点、可见数据和保留政策，未核实时不得声称其不会保存数据。

## 记录与失败样本

每个固定配置至少独立运行三次十题；每次使用[运行记录模板](../templates/金标准运行记录模板.md)单独建表，按 `tests/fixtures/golden/schemas/run-result.schema.json` 保存一份机器可读结果。目录 `<run-id>` 使用日期与短随机标识，JSON 中的 `runId` 再加 `-r01` 等重复编号，避免覆盖；均不含人名或 Key。计数、比率分母、未执行/不适用状态必须如实记录；没有评分时写“待评分”或 JSON `null`，不能填零冒充结果。

| 位置 | 内容 | 边界 |
|---|---|---|
| `data/eval-runs/<run-id>/raw/<repeat>/<case-id>/` | 原始响应、产品状态、请求计数、必要截图/trace 和文件 SHA-256 | `.gitignore` 已排除 `data/`；仅限受控本机，严禁复制 Key/Authorization/完整环境变量。保留失败与不利结果，不擅自删除。 |
| `docs/04-质量/records/golden-live/<run-id>/` | 脱敏后的 `run-<repeat>.md`、`run-<repeat>.json`、失败摘要和复核决定 | 入库前逐项检查题目外的个人信息、Key、请求头、端点中的凭据、工作区数据及截图；只用仓库相对路径引用脱敏证据。 |

每个失败题保留预期与实际差异、首次输出、用户介入、执行错误、图表或数值证据、E1–E4 阻断项、M1–M5 的 0–3 锚点、归因（产品/模型/外部服务/环境/标注待复核）及原始证据哈希。原始证据若含敏感信息，先在本地制作脱敏副本，记录删改范围和复核者，不把原文直接提交。截图/trace 可能含 Key 或私有状态，不能因路径在 `test-results/` 被忽略就视为安全。

只有一位评分者时标记“内部形成性评价”；正式阶段结论安排第二位独立评分者，记录分歧与裁决。报告全部通过和失败题、三轮波动、阻断项与限制；未经校准不把五项分数相加当百分制通过阈值。退出码 0、HTTP 200 和模型自述均不能替代附件内容、数学合理性、代码实跑、来源忠实与保存恢复检查。
