# 前端首轮审计与窄屏导航验收

日期：2026-09-30。基线 HEAD：`50ca781`，叠加已有未提交改动；本记录只归因本轮新增的导航切片。Node v24.13.0，Chromium 153.0.8010.12。

## 发现的前三项问题

| 优先级 | 问题与证据 | 用户影响 | 本轮处理 |
|---|---|---|---|
| P1 | 375px 设置页仍分配 200px 侧栏，内容实际仅 175px；`.app-shell:not(.rail-only)` 的优先级高于移动规则 | 模型配置表单严重挤压，入口导航逐字换行 | 修复断点规则，设置内容恢复 375px |
| P1 | ≤768px 的 `.sb-ws-list` 和三台 `.rail` 均隐藏，没有替代入口；全局导航只显示图标 | 无法切换工作区、导入备份，新手难以识别流程 | 增加文字导航与可键盘展开的工作区区域 |
| P1 | 375×900、首次引导打开时，编程台代码编辑区在固定高度分配中被挤到不可见，见改动前截图 | 难以审阅或手工编辑代码 | 留作下一独立切片；本轮未解决 |

其他发现：首次引导称「没有 Key，后面都跑不起来」，但无 Key 导入、范例浏览、手工拆解已经可用；深色引导步骤仍有白底浅字。两项均需后续修订，不能用本轮菜单主题验证覆盖。

## 选择范围与实际改动

选择全局导航，是因为它同时阻断首次配置与已有工作区恢复，修复边界集中在 `App.jsx` 与布局 CSS，可沿用全部存储和执行逻辑。实施没有引入新依赖或改写 React/Vite 架构。

- ≤768px 常显「1 读题 / 2 建模 / 3 编程 / 范例」，给出当前页语义。
- 非模态展开「工作区与设置」，复用原工作区操作；按钮声明展开状态与受控区域。
- Esc 收起、焦点恢复，工作区选择与菜单跳转后收起；桌面断点重置窄屏菜单。
- 主要导航和工作区操作目标高度至少 44px；沿用已有深浅色 token。
- 设计文档加入已核实实现的优先说明，避免早期「单页内切 tab」「Key 不上传服务器」描述被误用。
