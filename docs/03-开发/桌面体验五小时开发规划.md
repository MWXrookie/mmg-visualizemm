# 桌面体验五小时开发规划

版本：v1.7；制定日期：2026-10-01；完成日期：2026-10-02；状态：P0至P5出口全部通过，本开发包结束。总预算300分钟，累计实际约92分钟，未用预算不扩张为新任务。

## 目标与依据

参考用户提供的 `C:/Users/ASUS/Desktop/prompt辅助.md`，采用 BROKE：背景、角色、目标、关键结果、迭代。文件中的示例追问流程只是参考，不作为周期运行时等待确认的指令。

背景：MMG 是面向数模新手的三台工作区，用户反馈体验不好。此前审计已确认梳理台「生成代码」只跳页；全局流程引导已按用户要求移除，教程改为独立 `web/public/guide.html`。当前桌面侧栏默认收为图标，需要核对功能可发现性；其余候选问题需先复现，不能凭审美猜测。

角色：兼顾产品交互、视觉设计和前端实现的开发协作者。

目标：在一个五小时开发预算内，形成一个能完整验收的桌面体验改进包，使用户能找到功能、理解按钮动作、完成读题到编程的操作，并辨认等待、失败和成功状态。

并行设计目标：在保留当前风格、不大改布局的基础上，由开发者自主判断并提升现代感与科技感。视觉与动效属于本开发包的正式交付项，随交互阶段一起实施，不能最后才作为可有可无的装饰。

固定范围：桌面使用；保留宋体标题、低饱和色板和轻动效；不恢复应用全局引导；同步独立 HTML 指南。保留 AI 对话引导模式与必要提示。不推进手机适配、后端架构、真实模型付费评测或其他聊天的金标准开发。

## 美术与动态方向

方向为「安静的科技研究工作台」。保留现有三台布局、宋体标题、浅灰与靛蓝基调，通过细节增强精密感，而非更换整套视觉语言。用户已授权开发者自主选择细节，不为每个颜色、圆角或动效反复询问。

- 色彩与层次：统一背景、面板、边框和阴影的层级；可在活动导航、AI 状态和关键操作中少量使用冷蓝或青色点缀、极轻的渐变。正文区域保持平静，阅读对比优先。
- 组件质感：统一工具栏、标签、按钮、卡片的间距和圆角；选中态、焦点态与禁用态清楚。科技感主要由精确对齐、细线、状态标识和参数区少量等宽字体表达。
- 动态语言：交互反馈约120–160ms，面板与弹窗切换约180–240ms。优先复用现有动效 token，检查悬停、按下、展开、预览确认、生成与运行状态切换的一致性。动效不等待网络、不拖延操作、不重播整个页面。
- 持续动画只用于真实进行中的加载或运行状态，结束立即停止；尊重 `prefers-reduced-motion`。输入、编辑、滚动与焦点位置稳定，避免布局跳动。
- 不引入大面积霓虹、粒子背景、重玻璃模糊、3D 装饰、持续闪烁或长时入场动画；不加载远程字体和不必要的动画库。保留轻量实现与工作台内容密度。

美术与动效预算约40分钟，包含在以下阶段的预算内。优先用共享样式和组件规则覆盖三台；修复关键交互后做对应视觉收尾，不为跨页面统一而扩展成全面重构。

## 五小时顺序规划

时间是预计实际工作预算，包含实现、验证和记录，不是要求持续调用满五小时。阶段可以跨越多个45分钟触发周期，阶段出口通过后才进入下一阶段。

| 阶段 | 预算 / 累计 | 要做什么 | 交付与退出条件 |
| --- | --- | --- | --- |
| P0 桌面基线与范围锁定 | 30 分钟 / 30 | 检查现有改动与在途工作；在 1280×800、1440×900 走完整流程；记录交互问题及视觉基线，锁定共享色彩、层次和动效规则 | 有操作证据的问题清单、改前截图和设计细节清单；明确本包文件与依赖。功能问题先复现，视觉调整有明确改善依据 |
| P1 导航与按钮语义 | 45 分钟 / 75 | 修正「生成代码」跳页语义；检查导航文字可发现性；统一导航选中态、按钮反馈与共享面板质感；对齐指南 | 入口易辨认，按钮文案对应动作；空拆解与已有拆解均可导航；共享状态样式在深浅主题一致 |
| P2 读题桌面的信息层级 | 45 分钟 / 120 | 检查长题干、附件、精读与卡片空间；改善正文与工具栏层级、卡片边框和留白；克制处理切换反馈 | 长题干可连续阅读，题干与附件易区分；切换和调整正常；科技点缀不干扰正文，不损失内容 |
| P3 建模任务的编辑闭环 | 60 分钟 / 180 | 检查新建、编辑、预览、确认和进入编程；改善块标题、编辑态与预览态的层次，统一展开与确认反馈 | 可创建并保存完整块，预览不被误认作保存；刷新与跨台内容仍在；展开动效不引起焦点或布局异常 |
| P4 编程台的操作与状态反馈 | 60 分钟 / 240 | 检查生成、加载、运行、错误与结果；改善工具栏、参数和产出区层次，统一真实等待状态动效 | 当前阶段与错误处理清楚；输出和图表易辨；等待动效随真实状态结束；手动代码路径可用 |
| P5 集成验收与发布资料 | 60 分钟 / 300 | 核对完整流程、深浅主题、键盘和减少动态效果；目视比较三台改前改后，核对共享样式与动效；同步指南、设计记录，执行门禁 | 回归通过，桌面截图已目视检查；标题、布局与原风格延续，三台层次和动态统一；指南与代码一致，交付清单及遗留项 |

每阶段先检查后实施；已经达到出口的行为直接记录为通过，不制造改动。若前一阶段超时，压缩后续低价值视觉微调，保留 P5 至少45分钟。若已有工作造成同一文件修改冲突，先处理不冲突的项，不覆盖他人改动。

## 验收方式

- 桌面基线：1280×800、1440×900；必要时补1920×1080。深浅主题、长题干、长对话、多个拆解块和表格附件按风险选取。
- 模型交互使用确定性替身或失败响应，不读真实 Key、不产生付费调用。只能证明界面与请求流程，不声称真实模型质量。
- 浏览器使用隔离服务与临时数据库；允许短时启动自己的测试服务，结束清理，不重启用户现有服务、不操作真实工作区数据。
- 按变化风险进行构建、实际交互和必要持久化检查。P5 执行 `npm run check`、默认 `npm run test:browser` 与 `git diff --check`；真实 Pyodide 显式测试不因本次前端包自动扩大运行范围。
- 保存必要的桌面截图并目视检查，不仅依据 DOM 或命令成功判断体验通过；记录首次失败、修复及复跑，跳过不算通过。
- 美术与动效验收：三台使用一致的面板、控件和状态规则；宋体标题保留；深浅主题文字可读；动效不妨碍输入、滚动和焦点；减少动态效果模式下所有操作仍正常。截图验证静态美术，实际交互验证动效，不能用截图代替动态检查。

## 45分钟周期的推进与自迭代

五小时规划与45分钟唤醒是两层机制：前者规定总工作量和阶段，后者让同一任务继续。不是每45分钟开始一个新的五小时包，也不是每阶段必须恰好45分钟。

每轮只继续最早未通过的阶段，在本轮结束前记录：实际工作耗时、累计耗时、阶段状态、实际改动、验证证据、阻塞和下一项唯一动作。累计预算达到300分钟或提前完成全部出口时，停止扩大工作范围，交付结果；后续触发只检查新的用户指令或需要处理的变化，不自动开启下一包。

每轮复盘后迭代执行提示词的可变部分：更新进度与下一动作，删除过时信息，按失败原因加强验收。固定范围、用户偏好和安全要求不能自行放宽。没有新证据时记录「已复盘，执行规则维持」，不为了迭代而改写文字。迭代不能把未验证事项标为完成。

在启用自动化后，每轮通过 `automation_update` 恰好一次将更新后的进度与下一动作同步到本聊天的任务，保留45分钟频率、名称、状态、目标聊天和通知策略，不创建重复任务，不改别的聊天的任务。工具失败则如实记录，本轮不自行重复触发。
