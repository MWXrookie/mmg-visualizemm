> 版本：v3.0

> 状态：当前执行基线

## 1. 项目定位与最终目标

MMG_VisualizeMM 的长期定位不是“自动生成建模论文”，而是面向数学建模新手的本地优先 AI 辅导系统：帮助用户读懂题目、识别约束与目标、形成可解释的建模思路、生成并验证代码，同时保留用户决策权和证据链。

### 1.1 最终产品目标

在 2027-09 前形成可公开演示、可重复部署、可量化评价的 v1.0：

1. **学习闭环完整**：题目与附件导入 → 整体解读 → 划词精读 → 苏格拉底式建模引导 → 拆解块 → 代码生成 → Pyodide 运行与图表 → 工作区沉淀。
2. **AI 输出可核验**：重要判断可回到题干、附件、知识库来源或用户确认，不把“模型能回答”当作“结果正确”。
3. **单机部署可靠**：新用户可按文档在 20 分钟内完成安装、配置和第一个完整流程；工作区可备份、迁移和恢复。
4. **质量可持续**：核心逻辑有自动化测试，关键用户路径有回归用例，版本有发布清单、验收证据和变更记录。
5. **创新价值可证明**：围绕“数模语境角色判定、题干与附件联动、苏格拉底引导、浏览器内可视化验证”形成评测集、用户研究和阶段报告。
6. **项目可长期维护**：文档、架构、测试、决策与发布各有唯一入口；即使暂停数月，也能从路线图和记录恢复上下文。

### 1.2 v1.0 量化出口

| 维度 | v1.0 目标 |
|---|---|
| 核心流程 | 10 道覆盖不同题型的金标准用例全部跑通；无阻断级缺陷 |
| 角色判定 | 至少 100 条人工标注片段，宏平均 F1 ≥ 0.90 |
| 引用与证据 | 引用定位正确率 ≥ 0.90；严重无来源事实错误在金标准集上为 0 |
| RAG | 至少 50 个检索问题，Recall@5 ≥ 0.80；命中结果可追溯到文件与章节 |
| 数据可靠性 | 连续 30 次保存、刷新、重开和导入恢复无数据丢失 |
| 易用性 | ≥20 名有效试用者；核心任务完成率 ≥80%；SUS 目标 ≥75 |
| 教学效果 | ≥15 名用户完成前后测；理解/方案说明评分目标提升 ≥15%，样本不足时如实报告描述性结果 |
| 发布质量 | CI、自动化测试、人工冒烟、隐私检查、文档检查全部通过；发布 v1.0.0 |

这些数值是立项期目标，不是当前成绩。评测样本、评分规则和失败结果都要保留，禁止只报告有利案例。

## 2. 当前项目基线

当前代码已经越过“原型验证”阶段，处于“可用 MVP → 稳定研究型产品”的过渡期。

### 2.1 已具备

- React/Vite 三台工作流：读题、建模、编程和设置。
- BYOK 模型配置、OpenAI 兼容中继、SSE、直连与 HTTP(S) 代理。
- XLSX、CSV、PDF、TXT/Markdown 解析和 SQLite 工作区。
- 划词角色判定、双向引用、连续深挖、苏格拉底式提示。
- 59 张知识卡片，其中 41 张带交互演示。
- 方法库、知识卡片库、获奖论文组成的三源 RAG；当前为 1251 个知识块。
- 浏览器 Pyodide Python 执行、matplotlib 图表和附件数据挂载。
- 已核验的当前运行时架构图与基础构建流程。

### 2.2 进入长期开发前必须补齐

- 已建立 `npm test`、`npm run check`、Playwright 浏览器冒烟和 CI；lint、真实模型/Pyodide 浏览器回归仍待补齐。
- Node 单元/API 与浏览器冒烟已经分层；可复用生成/评测脚本已分类，一次性脚本已清理，人工验收证据仍需持续归档。
- 工作区已有 schema v1 JSON 备份、无覆盖导入和自动恢复回归；破坏性版本迁移演练尚未建立。
- AI prompt、评测集和模型结果尚未版本化，难以比较迭代收益。
- 浏览器全流程、异常路径、移动/窄屏和无障碍仍需系统验收。
- 普通局域网 HTTP 下 WebCrypto 不可用，API Key 会明文降级，需在产品化阶段降低风险。
- 缺少真实目标用户的任务完成率、学习效果与长期使用数据。
- 尚未形成正式版本、Release Notes 和创新项目结题证据包。

## 3. 单人 + AI 的开发方式

### 3.1 容量约束

- 采用 **两周一个迭代**，每个迭代最多承诺“1 个主要成果 + 1 个质量债务”。
- 每个迭代进一步拆成最多 **5 小时一个开发包**；每包形成可验收断点后停止，不为填满时间扩大范围。
- 同时进行中的主要任务不超过 1 个；新想法进入候选池，不直接打断当前迭代。
- 每 6 周安排 1 个整理迭代，只处理测试、文档、依赖、数据迁移和缺陷。
- 功能范围按“核心价值 > 正确性 > 可恢复性 > 体验 > 扩展性”排序。

### 3.2 人与 AI 的责任边界

| 角色 | 负责 |
|---|---|
| 项目作者 | 产品取舍、研究问题、用户访谈、数据伦理、安全边界、最终验收、发布和对外陈述 |
| AI | 代码草稿、测试生成、资料整理、文档同步、静态检查、回归分析和候选方案比较 |
| 共同完成 | 需求拆解、架构评审、缺陷定位、验收证据整理 |

AI 的输出必须经代码、测试、截图、数据或人工体验验证。涉及密钥、用户数据、许可证、研究结论和正式发布时，项目作者必须做最后审核。

### 3.3 每个任务的完成定义

任务只有同时满足以下条件才能标记为完成：

1. 需求和非目标明确，任务规模能在一个迭代内完成。
2. 代码、数据迁移和错误路径均已处理。
3. 自动化检查通过；无法自动化的部分有可复现人工步骤。
4. 对关键路径完成实际浏览器验收，不能只看构建成功。
5. 用户可见行为、API、架构或数据格式变化已同步文档。
6. 有回滚、恢复或兼容策略；不破坏既有工作区。
7. 结果进入一次小步提交，并附验收证据。

## 5. 阶段任务与验收

### 5.1 P1：工程质量地基

主要任务：

- 建立测试目录和统一脚本：单元测试、服务端 API 测试、浏览器冒烟测试。
- 添加 GitHub Actions 或等价 CI，固定 Node.js 版本和构建环境。
- 实现工作区 JSON 导出/导入、schema 版本、迁移和恢复失败提示。
- 盘点 `scripts/`：保留可重复使用脚本，一次性脚本使用后删除。
- 建立缺陷严重级别、发布检查表和验收记录目录。
- 补齐依赖许可、密钥泄漏、XSS/Markdown 清洗和代理错误测试。

验收条件：

- `npm run build`、`npm test`、静态检查和 `git diff --check` 可在 CI 中一次完成。
- 关键纯函数与数据转换具备单元测试；工作区 CRUD、解析、RAG 搜索具备接口测试。
- 新建工作区 → 导出 → 删除 → 导入后，题目、附件、拆解块、代码和整体解读一致。
- 仓库、构建产物、日志和数据库中不存在测试用 API Key。

### 5.2 P2：核心闭环可靠化

主要任务：

- 按[金标准评测集规范](../04-质量/金标准评测集规范.md)建立 10 道金标准题，覆盖评价、预测、优化、分类和几何等常见类型；当前不支持 PNG/JPG 上传，图像理解待产品具备对应输入能力后再纳入。
- 为模型调用记录 prompt 版本、模型、耗时和错误类型，但不记录明文 Key。
- 形成 Provider 兼容矩阵，验证通义、DeepSeek、OpenAI 和自定义兼容端点。
- 建立 RAG 小型评测集，测量召回、来源质量和无关片段率。
- 完成多问题拆解、划词结果进入拆解块、三台共享资料入口。
- 加固大文件、损坏文件、扫描 PDF、超时、断流、模型坏格式和本地缓存损坏等错误路径。

验收条件：

- 10 道金标准题从导入到运行出图均有可复现记录，阻断级通过率 100%。
- 30 次工作区保存/恢复无字段丢失；旧 schema 可迁移或给出明确恢复方案。
- RAG 每条命中都展示文件与章节；接口不可用时能静默回退而不阻断主流程。
- 流式失败、模型空输出和网络错误均有用户可理解的提示和可执行操作。

### 5.3 P3：差异化能力深化

主要任务：

- 把角色判定评测集扩展到 ≥100 条，定义标注指南和混淆矩阵。
- 构建“题干术语 ↔ 附件字段/工作表”对应关系，允许用户确认或纠正。
- 将苏格拉底引导从单段 prompt 升级为可测的对话策略：识别阶段、提问、等待、反馈、进入代码。
- 建立“题干证据 → 角色卡 → 拆解块 → 代码/结果”的可追溯关系。
- 对直接代做、错误自信、无证据推荐和越过停止短语等行为建立负向用例。
- 对知识卡片触发、解释准确性和交互价值做抽样审核。

验收条件：

- 角色判定宏平均 F1 ≥0.90，并公开失败类别和改进计划。
- 至少 30 组题干—附件字段映射，人工确认准确率 ≥0.90。
- 至少 30 条引导对话用例中，策略遵循率 ≥0.90，未授权直接给完整方案的严重违规为 0。
- 用户可以从关键建模决定回溯到原文、附件或知识库来源。

### 5.4 P4：产品化与小规模试用

主要任务：

- 制作 20 分钟内可完成的安装与首次使用流程；评估一键启动或 Docker Compose。
- 优化冷启动、Pyodide 加载、窄屏、键盘操作、深浅主题和错误恢复。
- 为局域网访问明确安全提示；评估本地 HTTPS 或一次性会话密钥方案。
- 设计匿名、知情同意的试用记录表，不默认上传用户题目或 Key。
- 招募 ≥20 名目标用户，完成观察式任务测试和简短访谈。
- 建立公开 issue 模板、反馈分类和版本节奏。

验收条件：

- 干净 Windows 环境按 README 在 20 分钟内启动并完成第一个工作区。
- Chrome/Edge 最新版、1440×900 和 1280×720 主流程可用；键盘焦点与 reduced-motion 通过检查。
- 核心任务完成率 ≥80%，SUS 目标 ≥75；所有阻断问题进入修复计划。
- 试用材料包含同意说明，数据去标识化，退出试用不影响软件使用。

### 5.5 P5：立项结题与 v1.0

主要任务：

- 执行前后测或对照/交叉设计，分析学习效果、使用时间和错误类型。
- 收敛 P0/P1 缺陷，冻结 v1.0 范围。
- 完成项目报告、演示视频、架构图、评测集说明、用户手册和答辩材料。
- 生成 Release Notes、第三方许可清单、隐私说明和可复现安装包。
- 发布 `v1.0.0`，建立后续 v1.x 维护节奏。

验收条件：

- v1.0 量化出口逐项给出“通过/未通过/证据不足”，不隐去失败项。
- 所有阻断级和高严重度缺陷关闭；中低级缺陷有公开限制和计划。
- 从全新克隆到构建、启动、导入样例、完成全流程可以被第三方复现。
- 立项申报、中期检查和结题材料中的数字均可追溯到原始记录。

## 7. 统一验收体系

### 7.1 每次合并或发布的最低质量门

1. 构建与语法检查通过。
2. 新增行为有自动化测试或明确说明为何只能人工验证。
3. 关键浏览器路径实际操作通过。
4. 数据迁移、异常恢复和安全影响已经检查。
5. README、架构、路线图、质量规范或决策记录按影响同步。
6. `git diff --check` 无空白错误，不提交临时脚本、密钥、数据库和构建产物。

详细命令和发布清单见 [质量保障与发布规范](../04-质量/质量保障与发布规范.md)。

### 7.2 缺陷严重级别

| 级别 | 定义 | 处理 |
|---|---|---|
| S0 阻断 | 数据丢失、密钥泄露、无法启动、核心流程完全不可用 | 停止发布，立即修复 |
| S1 高 | 核心结果错误、主要流程无可靠替代、严重误导用户 | 当前迭代修复 |
| S2 中 | 功能受限但有替代路径，影响部分用户 | 排入最近两个迭代 |
| S3 低 | 视觉、文案或低频体验问题 | 纳入整理迭代 |

### 7.3 阶段验收证据

每个阶段至少保留：

- 命令输出或 CI 链接；
- 自动化测试报告；
- 手动用例勾选与截图；
- 评测集版本、模型配置和结果摘要；
- 用户研究的匿名原始记录与分析方法；
- 已知限制和下一阶段决策。

## 8. 创新项目立项映射

### 8.1 建议研究问题

- **RQ1**：数模语境角色判定和双向引用能否提高新手对题意、目标和约束的识别准确率？
- **RQ2**：题干—附件字段联动是否能减少数据理解错误和无效建模尝试？
- **RQ3**：苏格拉底式分阶段引导相比一次性答案，是否能提高用户独立说明建模方案的能力？
- **RQ4**：本地优先、BYOK、浏览器执行的架构能否在隐私、部署成本与可用性之间取得可复现平衡？

### 8.2 创新点表述原则

可申报的创新组合包括：

1. 面向数学建模文本的角色判定与可回溯证据链；
2. 题干自然语言与结构化附件的联动理解；
3. 以用户决策为中心、可测量的苏格拉底式引导流程；
4. RAG、知识卡片和浏览器 Python 验证组成的学习闭环；
5. 适合个人自托管的低成本隐私架构。

“创新”应通过竞品矩阵、文献、评测集和用户数据证明，不使用“全球首创”等无法核验的绝对表述。

### 8.3 预期成果

- 可公开运行的 v1.0 软件及源代码；
- 角色判定、RAG、引导策略和金标准题评测集；
- 当前架构、测试、隐私和部署文档；
- 用户研究数据字典、分析报告和项目总结；
- 演示视频、答辩材料和阶段成果截图；
- 具备条件时形成论文、软件著作权或后续竞赛成果，但不把未确定成果写成必达项。

立项摘要和待补字段见 [创新项目立项准备](../05-立项/创新项目立项准备.md)。

| 风险 | 触发信号 | 控制措施 |
|---|---|---|
| 单人容量不足 | 连续两个迭代延期 | 缩小范围、冻结 P2、安排整理迭代 |
| AI 输出不稳定 | 同题结果波动或严重误导 | 固定评测集、prompt 版本、来源追溯和人工确认 |
| 数据丢失 | 工作区无法恢复 | schema 版本、导入导出、迁移测试和备份 |
| 密钥或隐私泄露 | Key 出现在日志/数据库/提交 | 自动扫描、日志脱敏、安全上下文提示 |
| 依赖/CDN 不可用 | Pyodide 或模型资源加载失败 | 明确错误、缓存/镜像评估、离线降级 |
| 研究结论失真 | 样本少、选择性报告 | 预先定义指标，保留失败结果，区分探索与验证 |
| 文档再次过期 | 文档和代码相互矛盾 | 以文档地图为入口，按变更触发器同步更新 |
| 范围膨胀 | 同期出现多个新平台需求 | WIP=1，任何新平台能力先给用户证据和维护成本 |

## 10. 维护节奏
