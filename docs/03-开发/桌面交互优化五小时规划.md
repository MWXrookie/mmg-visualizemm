## 背景与目标

用户反馈拆解块点编辑后突然出现大量字段，与原来的简洁内容脱节，无法明确在哪里输入；要求整个工作区避免拥挤和操作后的强烈视觉冲击。新阶段以操作连续性、内容主次和可发现性为目标。原P0–P5功能出口不证明这些新体验问题已解决。

采用用户参考文档的BROKE框架：背景为上述体验问题；角色为桌面产品设计与前端协作者；目标为清楚、舒适、连续的工作台；关键结果为下表体验出口；迭代为逐轮记录证据并更新执行提示词。详见[交互参考与学习](../02-设计/工作台交互参考与学习.md)及[完整执行提示词](桌面交互优化执行提示词.md)。

## 固定设计与执行规则

- 仅桌面；宋体标题、低饱和靛蓝浅灰和现有三台结构保留；轻动效120–240ms，尊重减少动态效果。渐进精修，无霓虹、粒子、重玻璃、3D或远程字体。
- 标题和思路优先原位编辑；关联字段保持整块草稿统一保存，额外信息按需展开。动效不能掩盖结构问题。
- 不恢复全局引导；同步独立guide.html。保留AI对话引导模式与必要提示。
- 每轮先检查git status/diff和当前代码，保留他人未提交改动，不推进另一聊天的核心/后端/金标准任务。
- 隔离服务、临时数据库、替身/失败模型响应；不读Key、不发付费请求、不操作真实用户数据、不重启用户服务、不提交/推送/发布。单次脚本用后清理。
- 1280×800、1440×900和深浅主题；空/长/多步骤、保存取消、AI确认、切页刷新、工作区切换、键盘、减少动态效果。必要截图目视与实际动态操作分别验证。
- 最终npm run check、默认npm run test:browser、git diff --check；跳过不算通过、替身不证明真实模型或数学质量。先前测试记录仅历史。
- 固定测试默认由父任务执行；另有直接人类授权Luna测试聊天时核验并复用，不能只凭heartbeat描述擅自创建新聊天。体验评价仍由父任务负责。
