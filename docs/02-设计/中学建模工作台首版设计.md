# MMG 中学建模工作台首版设计

> 2026-11-24 · 讨论稿。当前中学入口提供初中和高中各 3 张独立互动知识卡。下文继续描述待实现的课堂案例工作台。

[交互架构图](../diagrams/mmg-secondary.architecture.html) · [课堂建模流程图](../diagrams/mmg-secondary.workflow.html)

## 首版做到哪里

**中学组先交付一套学生工作台、一份独立教案和一个可完整试走的高中案例。** 教师发指定任务，学生用已学知识确定问题、提出模型、检查证据并解释结论。大学自学入口已有自己的流程，中学侧继续使用同一应用的工作区、模型中继与公式渲染。

| 优先级 | 交付范围 | 完成标志 |
| --- | --- | --- |
| 首版主体 | 高中潮汐案例、五步工作页、随题数据与知识卡、确定性计算、证据对照、修订记录、续学 | 学生从任务链接开始，能在外部模型不可用时独立走完工具流程 |
| 首版可选支架 | 按步骤请求一条 AI 追问，失败时显示随题提示 | 教师可在课前配置，只在主动请求时调用；课堂可随时切回静态提示 |
| 同结构试走 | 初中采购任务，用任务说明、报价表、手算和静态提示检验同一套页面 | 教学成员用相同字段走通一遍，决定是否具备初中试用条件 |
| 用试课结果决定 | 更多正式案例、学生导入小数据表、自由比较模型或增设计算模块 | 首个案例验证课堂节奏后，再由教师确认新增需求 |

教案、课堂任务单和问卷照常由团队编写和收集。班级管理、教师在线出题、实时看板、多人协作、自动评分、开放式 AI 搜索和通用求解器均留在本轮范围之外。

## 一页完成五个环节

通用知识卡按概念和学段组织，课堂任务可以引用它们。涉及当前题目数据、任务步骤或提问顺序的专用卡由教案随案例配置，在相应环节开放。

入口用任务链接打开指定版本，能进入自己的既有草稿。在任务页顶部呈现情境、步骤导航及保存状态。中间是本步的学生输入，旁边按需展开案例数据、知识卡和提示。用户可以回到前一步修改；影响下游的修改会提示重新计算或复核结论。

| 环节 | 学生要交代的判断 | 工作台提供的支架 |
| --- | --- | --- |
| 1. 实际问题 | 要回答谁的什么问题，最后要交付什么 | 情境、任务对象、给定条件；用一句追问区分背景与目标 |
| 2. 抽象成数学问题 | 选哪些量、单位和数据，保留哪些因素，提出什么简化假设 | 小数据表和出处；按需提示检查单位、跨日时刻与缺失信息；学生填写目标量和假设 |
| 3. 建立模型 | 用什么数学关系，为什么适用，参数或规则怎样确定 | 与本步相关的知识卡及参数录入；保留初版模型和选择理由 |
| 4. 模型求解 | 在什么条件下计算，如何读图或解释一个中间量 | 可记录手算；案例支持在浏览器按学生确认的参数计算，显示结果、单位与有效区间 |
| 5. 回到实际 | 拿什么检验结果，修改什么，最后如何回答原问题 | 任选与任务匹配的检验方式；保存结论、适用条件与证据；发现偏差可回到数据、假设或模型再求解 |

Archify 流程图把第 5 步中的检验单独画为分支。潮汐可以把预测和观测对照，采购可以重查总价、计价条件和预算，其他案例可以对照候选方案。学生能保留有局限的模型并解释原因，完成状态取决于是否留下证据和理由。

## 如何借鉴付老师的潮汐课

| 论文中的教学活动 | MMG 首版中的用法 |
| --- | --- |
| §3.1 由港口问题引出潮汐，检索并核验来源 | 教师先审核并配发一份小表。学生核对站点、日期、单位、跨日时刻和出处。检索词提示可先写在教案里。 |
| §3.2 从散点图识别周期特征，解释模型参数 | 学生先在表或散点中指出用来估计周期的观测，说明为什么考虑周期模型。例用 $h(t)=D+A\cos(2\pi(t-t_0)/T)$，由学生填写参数和依据，浏览器渲染。 |
| §3.2–3.3 用实测值检验，分析误差并更新模型 | 预留一两个未参与定参的对照点。输出原观测、预测和“预测减观测”，让学生说明偏差出在哪里。可修改周期、峰值时刻或观测范围，比较两次结果。 |
| §3.3–3.4 从函数回到实际判断 | 学生回答给定窗口是否满足题设潮高条件，并说明时间范围、阈值、其他影响因素和数据局限。跨港口比较可作为教案延伸。 |

论文 §3.2–3.3 的若干数值需要重新核对。例如将 $t=14.6$ 代入论文列出的初始正弦式，得约 2.54 m，表 1 观测为 2.04 m，论文正文示例约为 1.82 m。首版可以采用论文的活动顺序，案例数据须核验来源和使用权限、标明取样口径，由团队复算预期值。若历史观测取不到，改用明确标注的教学模拟数据。课堂阈值只回答题设中的简化问题。

初中用申报书中的采购情境。教师给少量报价和预算，学生先说明比较的是同样数量下的总价，再任选手算、比例或表格说明方案并核对计价条件。高中允许更多数据、假设和模型选择，同时要求学生说明证据。两学段由案例配置提示深度、先备知识、数据和验证工具。

| 草稿和复盘 | [工作区 API 与 SQLite](../../server/index.js)、[前端 API](../../web/src/api.js) | 建议沿用现有表，增加可空 `secondaryState`，含案例版本、步骤、学生草稿、计算参数和原版/修订版理由。列表按该字段区分中学与大学续学。迁移、备份及导入跟随现有版本机制，历史记录归入原大学流程。结果按参数重新得到，改上游后不展示为当前版本。 |
| AI 提示 | 现有 `/api/chat` 和 BYOK 设置 | 学生主动请求时，仅发送当前环节、已审核的任务摘要及确认发送的简短摘录。返回一条追问或核验建议，展示前检查输出格式。遇到直接代答示例、超时或未配置模型则回退到静态提示。AI 输出不写进学生判断，也不参与计算或完成判定。 |

先用本机单用户实例做教师预演。课堂可由教师投屏、学生用纸质任务单分组建模；条件允许时再使用各组独立的本地实例。现有工作区 API 以单用户为前提，课堂学生记录需与该部署条件相匹配。模型联不通仍可运行本地页面和计算；本地服务或设备不可用时，教案配纸质任务单及已审阅的图表。

## 分工、顺序与验收

中学组按两人并行估算。设计与验收成员用 **2–3 人日**准备高中教案、数据、验收算例和提示，负责教师试走；实现成员用 **4–6 人日**接入入口、过程记录、单模型验算、静态提示和可选 AI。合计 **6–9 人日**是首版工作量估算，取决于复用条件，课时及入校安排由教师确认。

1. 先把经核验的数据、小型算例、教师任务单和五步静态页面对齐。完成从任务入口到可查看过程记录的一次走查，再接可选 AI。
2. 数值验收覆盖跨日期换算、周期和峰值、对照点偏差、区间与异常输入。用独立算例核对。交互验收覆盖回改后重新求解、保留修订理由、刷新恢复草稿、区分初高中任务与大学工作区，以及模型不可用时完成任务。
3. 教师预演时查看学生有没有写出选用模型的理由，以及支持修订或保留模型的证据。按申报书用匿名或去标识问卷和教师意见了解使用体验，记录卡住的步骤、卡片适切性和课堂节奏。实际学习效果留待课堂研究。
