# MMG_VisualizeMM 技术框架与运行时架构

> 状态：当前实现核验版（2026-09-30）。
> 本文以 `web/`、`server/` 和 `package.json` 为事实来源，描述已经存在的运行时组件、数据流与边界；规划中的 Docker 沙箱、独立向量数据库等不计入当前架构。

## 1. 当前技术基线

| 层 | 当前实现 | 代码依据 |
|---|---|---|
| 前端应用 | React 18 + Vite 6，JavaScript/JSX；读题、建模、编程和设置共用一个工作区状态 | `web/src/App.jsx`、`web/vite.config.js` |
| 浏览器存储 | `localStorage` 保存模型配置、对话面板状态、收藏、主题和当前工作区 ID；安全上下文中 API Key 使用 WebCrypto AES-GCM | `web/src/store.js`、`web/src/pages/Workbench.jsx`、`web/src/pages/Modeling.jsx` |

| 服务端 | Node.js + Express 4，默认监听 `0.0.0.0:3088`；提供静态托管、JSON API、SSE 中继、附件解析和工作区 API | `server/index.js` |
| 上游网络 | OpenAI 兼容 `/chat/completions`；支持直连或 HTTP/HTTPS 代理，流式请求由服务端转成 SSE 并回传完成原因 | `server/index.js`、`server/upstream.js` |
| 工作区存储 | Node 内置 `node:sqlite`，数据库为 `data/mmg.db`；保存题目、分页文本、附件、拆解块、代码和整体解读；数据库及 JSON 备份 schema 当前为 v1 | `server/index.js` |

| 知识库 | 本地三源 RAG：方法库、知识卡片库、获奖论文；当前扫描为 1251 个知识块，向量缓存写入 `data/knowledge_cache.json` | `server/knowledge.js` |

## 3. 组件与边界核验

### 3.1 浏览器信任边界

- React 前端承载读题、建模、编程和卡片交互。
- React 范例页读取同源静态目录，附件预览复用 `/api/parse`；不自动创建或覆盖工作区，也不调用模型。
- API Key、模型配置、对话面板状态和收藏保存在浏览器，不写入 SQLite。
- API Key 仅在 HTTPS、`localhost`、`127.0.0.1` 等可用 WebCrypto 的安全上下文中以 AES-GCM 加密；通过普通局域网 HTTP 访问时会降级为明文存储并在设置页告警。
- Python 代码由 Pyodide 在浏览器内执行，服务端没有 Python 执行器、Docker 沙箱或任务队列。

### 3.2 单机自托管服务边界

- Express 同一进程负责 API、静态文件、模型中继、附件解析、工作区读写和 RAG 检索入口。
- `npm run build` 先校验十道正式题的哈希和可再分发标记，再把题干、附件及署名复制到静态产物；`expected.json`、基线代码、原始来源快照和本地兼容赛题不进入公开目录。公开目录中出现未登记文件时构建失败，不自动删除。
- `data/mmg.db` 只保存工作区业务数据，不保存 API Key。
- 工作区 JSON 备份只导出业务字段和版本元数据；不包含浏览器中的 API Key、模型设置、对话面板状态或偏好。
- `data/knowledge_cache.json` 是可重建的向量缓存；知识源来自 `docs/07-论文库/`。
- `server/upstream.js` 负责直连或代理传输，并对网络错误做不泄露凭据的归一化。

### 3.3 外部服务边界

- 对话模型是用户配置的 OpenAI 兼容端点；浏览器随单次请求把 Base URL、模型名和 API Key 交给 Express，中继完成后不持久化这些凭据。
- Embedding API 是可选外部依赖。服务端可优先读取 `server/.env.local` 的 Embedding 配置，也可使用请求携带的配置；不可用时继续使用本地哈希向量。
- Pyodide 首次加载依赖 jsDelivr CDN，因此“浏览器内执行”不等于首次使用完全离线。

## 4. 关键数据流

### 4.1 对话与代码生成

1. 前端从本地设置解密 API Key。
2. 前端向 `/api/chat` 或 `/api/chat/stream` 发送 OpenAI 兼容消息与 BYOK 配置。
3. Express 通过 `server/upstream.js` 调用外部模型；流式响应以 SSE 增量回传，并在最终帧传回上游 `finish_reason`。整段接口也返回同一完成原因。
   读题台整体解读默认仅把已解析表格的前三行预览发往该模型。用户可为下一次解读显式选择符合边界的小表，把当前已保留行加入本次消息；前端限制 12 行、8 列、4 KiB/表、16 KiB/次选择，并在检索内容组装后检查完整请求不超过 100000 字节。选择不持久化，不作用于建模、编程或其他请求；“已保留行”不等于原 XLSX 全部行。
4. 读题、建模和编程页面消费回复。编程页遇到明确的非正常完成原因（例如 `length`）时保留已生成代码并标明未完成，停止自动修复与追加批注请求；完成原因缺失时继续使用代码结构检查提示风险。生成的代码由用户在浏览器 Pyodide 中运行。

### 4.2 RAG 检索与提示词组装

1. 前端先调用 `/api/knowledge/search`。
2. 服务端对方法库、卡片库和论文块执行“向量相似度 + 关键词 + 类型权重”的混合检索。
3. 服务端返回 top-k 命中片段；前端 `formatKnowledgeContext()` 把片段组装进 system prompt。
4. 前端再把完整 prompt 发送到对话接口。也就是说，RAG 服务负责检索，提示词注入发生在前端。

### 4.3 附件与工作区

1. 浏览器把附件转为 base64，提交 `/api/parse`。
2. 服务端解析 XLSX/CSV/PDF/TXT/Markdown，返回表格或结构化文本。CSV 在 5MB、2 万数据行内全量返回，超过上限时报错而不截断；XLSX 仍是每表前 100 行的预览数据。
   小表选择发生在浏览器内，显示工作表名、当前已保留行列数和将发送文本的字节数。超出单表或合计边界的表不能选择；用户未选中的表仍只进入前三行摘要。附件单元格作为不可信数据，不授予指令权限。
3. 前端把题目、附件、拆解块、代码和整体解读写入工作区 API，最终落到 `data/mmg.db`。附件解析后先将附件与当前题干保存成功，再在页面标记为完成；常规自动保存使用普通异步请求，离页时对小请求用 `keepalive`、大请求尝试同步兜底。浏览器突然终止时仍不能保证其他尚未完成的写入。
4. 编程台从当前工作区状态中的已解析表格生成 CSV，挂载到 Pyodide 的 `/data` 目录；因此旧工作区中已被截断的 CSV 需要重新上传，才能在 Python 中取得全量数据。
5. 用户可把单个工作区导出为 `mmg-workspace-backup` / `schemaVersion: 1` JSON；导入先校验格式与版本，再以新 ID 写入 SQLite，不覆盖已有工作区。

## 5. 当前 API 面

| 能力 | 接口 |
|---|---|
| 模型连通性与对话 | `POST /api/test-key`、`POST /api/chat`、`POST /api/chat/stream` |
| 附件解析 | `POST /api/parse` |
| 工作区 CRUD | `GET/POST /api/workspaces`、`GET/DELETE /api/workspaces/:id` |
| 工作区备份恢复 | `GET /api/workspaces/:id/backup`、`POST /api/workspaces/import` |
| 附件数据导出 | `GET /api/workspaces/:id/attachments/:idx/data.csv`、`data.json` |
| 知识库 | `GET /api/knowledge/stats`、`POST /api/knowledge/search` |
| 健康检查 | `GET /api/health` |

## 6. 当前架构明确不包含

- 服务端 Python/Docker/microVM 代码执行沙箱；
- WebSocket、消息队列或独立 Worker；
- 独立向量数据库；
- 账号、权限和多租户隔离；
- API Key 服务端持久化；
- PDF OCR 和旧版 XLS 解析。

这些能力若后续实现，应在代码、边界和安全约束落地后再进入运行时架构图，不能用规划替代现状。


### 2026-11-06 运行诊断与会话历史补充

依赖加载器与生成/改进提示词共享 pythonEnvironment.js 的包清单。最近运行结果与可选删除的历史记录分开保存于按工作区隔离的前端会话 Map；跨台返回可恢复最近输出、错误及图像。选择删除只删历史条目，可撤销最近一批；不删除代码和当前结果，不复用运行序号。刷新页面会清空这些会话结果，不写数据库。AI改进携带最近运行异常与有界输出及代码版本提示；这不是自动修复成功的保证。详见[工作台交付说明](../04-质量/records/2026-11-06-workbench-delivery.md)。
