# MMG 共同开发与交接

> 2026-11-24 · 大学组和中学组共用

## 分工和交付

四人分成大学组和中学组。每组由一人负责设计、试走和验收，另一人负责实现及回归检查。实现时可以用 AI 辅助，每位成员对自己提交的判断、代码和证据负责。

| 分工 | 大学组 | 中学组 |
| --- | --- | --- |
| 设计与验收 | 用自己带来的题目试走，写清学生在读题、建模、编程各步要做什么；记录可复现的卡点 | 和教师核对先备知识、任务数据、课堂提问及学生要作出的判断；用同一案例试走教案和工作台 |
| 实现与回归 | 实现大学分区的导入和续学，以及三台之间的衔接 | 实现中学任务入口、随题支架、计算对照和修订记录 |
| 两组共同维护 | 统一入口、附件解析、工作区与备份、模型中继、知识卡片基础组件和浏览器计算 | 共用改动在 PR 中写明影响，并用两组的入口或用例复核 |

## 一项任务怎样交接

1. **开工。** 在 Issue 或 PR 说明任务对应的页面或案例、接手人、基线分支和验收步骤。中学任务一并确认学生需要自己完成的判断。
2. **开发。** 从任务基线建立短分支。先用可分享的小样例重现问题，再实现并记录影响范围。两组碰到同一模块时，先确定谁提交共用变更。
3. **试走。** 负责验收的成员按用户的入口操作，保存复现步骤和实际结果。提交前执行项目质量门。对真实模型、真实 Pyodide 或课堂试用，分别写清实际覆盖。 [质量保障与发布规范](../04-质量/质量保障与发布规范.md)
4. **交接。** 推送分支，在 PR 放入下方记录。接手人从指定提交运行第一条验收步骤，能复现结果后再接下一项。公开仓库使用可分享的样例和经过检查的证据。
