# MMG_VisualizeMM 项目治理与文档规范

> 状态：当前规范
> 适用方式：单人负责人 + AI 协作
> 更新日期：2026-09-27

## 1. 唯一事实来源

发生冲突时按以下顺序判断：

1. 当前代码、可重复测试和用户最新决定；
2. [当前运行时架构](../01-产品/技术框架与架构.md)；
3. [长期开发规划](../03-开发/开发规划与验收.md)；
4. [产品需求文档](../01-产品/PRD.md)；
5. 调研、原型和历史报告。

旧文档不能覆盖当前代码。发现冲突时先验证事实，再修正文档，不把过时描述复制到新材料。

## 2. 文档职责

| 文档 | 回答的问题 | 更新时机 |
|---|---|---|

| `01-产品/PRD.md` | 为什么做、为谁做、长期需要什么 | 产品定位、目标用户、范围变化 |

| `03-开发/开发规划与验收.md` | 接下来做什么、何时完成、如何验收 | 每两周更新状态，每季度重排 |
| `04-质量/质量保障与发布规范.md` | 固定质量门和发布流程是什么 | 测试、CI、发布或安全规则变化 |
| `05-立项/创新项目立项准备.md` | 如何把项目转为可申报、可答辩成果 | 学校模板、研究设计、指标变化 |

| `prototypes/` | 设计探索和生成产物 | 仅在设计迭代时更新，不作为实现事实 |

## 3. 文档状态

- **当前规范**：持续维护，可作为执行依据。
- **当前实现**：描述已验证代码，不包含未实现规划。
- **规划目标**：未来承诺，必须带周期和验收条件。
- **参考材料**：调研、论文、原型或素材，不直接代表决定。
- **历史快照**：保留当时证据，不再表示当前状态。
- **生成产物**：由工具生成，应与源文件和校验记录一起维护。

每份重要文档顶部应注明日期和状态。禁止用“已完成”描述只写了代码但未验收的功能。

## 4. 单人 + AI 工作流

1. 从路线图选一个能在两周内完成的结果。
2. 写清目标、非目标、风险和验收条件。
3. 让 AI 协助检索代码、提出方案、实现、补测试和同步文档。
4. 项目作者审核架构、安全、数据、许可证和用户体验。
5. 执行自动检查与真实浏览器用例。
6. 记录证据、限制和未解决问题。
7. 小步提交；发布时再形成版本说明。

AI 不是项目责任主体。密钥、用户研究数据、对外结论和发布操作必须由项目作者把关。

执行层面按最多 5 小时的独立开发包拆分。每包只能有一个主要目标，结束时必须形成可验收成果、执行适用检查并停止汇报；不得为了填满时间扩大范围，未完成事项顺延到下一包。

## 5. 变更触发器

| 变更 | 必须同步 |
|---|---|
| 新增/删除用户功能 | README、PRD、路线图、相应用例 |
| 改动 API、存储或数据格式 | 架构、迁移说明、接口测试 |
| 改动运行时组件或信任边界 | 架构 JSON/HTML/PNG、架构文档、安全检查 |
| 改动 AI prompt、RAG 或评测规则 | 版本号、评测集、结果记录、已知限制 |
| 增加外部依赖 | 许可证、隐私/网络边界、部署说明 |
| 发布版本 | 质量记录、Release Notes、文档导航和已知问题 |

## 6. 稳定决策记录

| ID | 决策 | 原因 | 重新评估条件 |
|---|---|---|---|
| D-001 | 单用户、本地优先、自托管 | 适合目标用户和单人维护 | 明确出现多用户协作需求 |
| D-002 | 对话模型采用 BYOK，中继不持久化 Key | 降低运营与密钥托管责任 | 有合规的托管产品计划 |
| D-003 | Python 默认在浏览器 Pyodide 执行 | 零部署、隔离服务端风险 | 题型确实需要浏览器无法承担的计算 |
| D-004 | SQLite 作为工作区存储 | 单机数据量足够、维护成本低 | 出现并发、多设备或大规模数据 |
| D-005 | RAG 先用文件 + JSON 缓存，本地哈希可降级 | 可离线、容易恢复 | 评测证明检索规模或质量成为瓶颈 |
| D-006 | AI 是教练，不默认代做完整方案 | 产品定位与教学目标 | 产品定位经正式评审改变 |
| D-007 | 开发计划按最多 5 小时的独立开发包执行 | 控制单次额度，让多个项目可并行推进并保持可验收断点 | 用户明确调整时间或额度策略 |

新增重大决策时在本表追加；若决策被替代，保留原记录并注明替代 ID。

## 7. 文件与归档规则

- 文档放入对应分类，不在 `docs/` 根目录堆放临时文件。
- 一次性脚本用后删除；会重复使用的脚本放入 `scripts/` 并写明用途。
- 历史报告不伪装成当前状态；必要时放入 `archive/` 或在标题标记“历史快照”。
- 生成图表保留源文件、交付文件和校验回执；不要只保留截图。
- 不提交 `.env.local`、API Key、运行数据库、用户原始隐私数据或本机构建产物。
- 外部发布前检查链接、许可证、引用、隐私和绝对化创新表述。
